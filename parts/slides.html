{{CHROME:02 · The solution · Recommendations}}

One campaign per model.
Language and store travel with the request.

Model

Campaign id — similar items, bought together, personalized. One each, for every language.

Language

displayAttribute=name_es — the response carries the shopper’s language.

Store

additionalFilters — the same availability clause, joined with AND to the campaign’s own filters.

GET /recommendations/v2/recommend/campaigns/{campaignId}?clientUUID={uuid}&itemId=HM-GRO-0116
    &displayAttribute=name_es&additionalFilters=availability == "ST-ES-MAD-01"&filtersJoiner=AND&token={trackerKey}

{{CHROME:02 · The solution · Front end}}

The storefront calls Synerise directly.

  • Tracking code in the page. The SDK gives every visitor a profile UUID.
  • Tracker key on every call. Public by design: it reads search and recommendations, never configuration.
  • Events close the loop. Search clicks and recommendation views train ranking.
  • No API key in the browser. Index and campaign setup stays server-side.

{{CHROME:04 · Summary}}

What to watch, and what already holds.

Watch out

  • A bad filter never errors. A typo or a non-filterable attribute drops the filter and returns the whole catalog. Check totalCount.
  • Recommendations filter only on AI-engine filterable attributes. Anything else is ignored, with HTTP 200.
  • No recommendation matches = HTTP 404 REC-016, not an empty list. Treat it as an empty rail.
  • Facets: repeat the parameter. …/query?query=milk&facets=brand&facets=price. Written as facets=brand,price it asks for one attribute called “brand,price” and returns no facet.
  • Sorting switches off merchandising. sortBy disables boosts, pins and rules.
  • Ranking weights are not on by default. An index without scoring weights ranks in catalog order: no popularity, no personalization. Set personalized, transactionsPopularity and the per-endpoint personalizationWeights.

Designed to holdno need to worry about

  • == on an array matches one whole element. store_11 never matches store_111; letter case does not matter.
  • The store filter reaches the facets. Brands the store does not sell drop out of the brand facet.
  • The tracker key in the page is by design. It reads search and recommendations; it cannot read or change configuration.
  • One campaign serves every language. displayAttribute returns the shopper’s names.
  • Leaving the reco row out is server-side. Counts, facets and pages stay right.
  • Catalog updates reach the index in minutes, with no rebuild. A config change rebuilds in 6–10 minutes while the index keeps serving.
  • Store-scoped calls are fast. About 100 ms each; twenty in parallel (slide 12) are fine.
